# Dataset Generator

[![CI/CD](https://img.shields.io/github/actions/workflow/status/KevinDeBenedetti/dataset-generator/ci-cd.yml?style=for-the-badge&label=CI%2FCD)](https://github.com/KevinDeBenedetti/dataset-generator/actions/workflows/ci-cd.yml) [![Release](https://img.shields.io/github/v/release/KevinDeBenedetti/dataset-generator?style=for-the-badge)](https://github.com/KevinDeBenedetti/dataset-generator/releases) [![License](https://img.shields.io/github/license/KevinDeBenedetti/dataset-generator?style=for-the-badge)](LICENSE)

> Turns your files, web pages and GitHub repositories into question/answer
> datasets, reviewed as drafts and published to your Hugging Face account — for
> anyone training or evaluating language models.

## Features

- **Hugging Face as the source of truth**: the **Datasets** section reads every
  published dataset from the Hub with your own token — data table, rendered
  card, per-column statistics, files and version history with row-level diffs
- **Four sources**: uploaded files (PDF/image, transcribed by your LLM),
  single web pages, GitHub recipes — your public repos as the model sees
  them, saved as the sources of a dataset — and your resumes on Reactive
  Resume, regenerated by themselves on a schedule if you like
- **Drafts before publication**: every generation waits as a draft (a numbered
  run, pairs idempotent by content hash) to review, check for duplicates and
  rule failures, then publish as a **private** dataset repo
- **Vector collections**: embed a split of a published dataset into Qdrant
  with your endpoint's embedding model, then search it and run a retrieval
  test that shows which questions don't find their own answer
- **Two models, your own keys**: one LLM for every step and one embedding
  model, on each user's OpenAI-compatible key and endpoint, the LLM picked on
  the **Models** page
- **GitHub datasets**: Q&A pairs and a retrieval corpus from your whole GitHub
  account, generated on demand from the **GitHub** page and run by a worker
- **Per-user isolation**: datasets, runs and settings belong to their owner;
  keys are encrypted at rest and never returned by any route

## Prerequisites

- Docker Desktop — the stack runs with Docker Compose
- An OpenAI-compatible API key, and a Hugging Face token with write access

## Usage

```sh
cp .env.example .env   # then add your keys
make dev               # builds if needed, streams the logs; Ctrl-C stops the stack
```

The web app listens on `http://127.0.0.1:3020`, the API on `8020`; `make help`
lists every target.

→ Full usage guide: [Getting Started](https://kevindebenedetti.github.io/dataset-generator/getting-started)

## Development

```sh
make lint                      # server and client linters
make test                      # the suite, against a throwaway Postgres (needs Docker)
uv run prek run --all-files    # every git hook
make api-client                # regenerate the committed OpenAPI contract and the client
```

→ Tests, hooks and the API contract: [Development](https://kevindebenedetti.github.io/dataset-generator/development)
